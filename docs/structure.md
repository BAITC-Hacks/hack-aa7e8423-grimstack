## Область документа

Документ описывает текущую структуру репозитория и правила совместной работы.
Как устроен расчёт, описано в `docs/design.md`, откуда берутся данные —
в `docs/data-profile.md`.

Владельцы: **А** — Aliar (ядро, данные, AI, Docker), **Б** — API, **Ф** — фронт и README.

## Правила разработки

Правила задают границы модулей, общий контракт и условия воспроизводимого запуска.

### Слои и зависимости

Зависимости идут только вниз: `api → engine → ingest`.

- `engine` и `ingest` не импортируют FastAPI; это проверяет `tests/test_boundaries.py`.
- Роутер получает параметры, вызывает одну функцию ядра и возвращает модель из
  `contracts.py`. Считать в роутере нельзя.
- Ядро вызывается только через `engine.run / history / meta` и
  `ingest.load_default / load_uploaded`.

### Единый контракт

Формы данных между частями задаёт только `app/contracts.py`.

- Фронт повторяет его в `src/api/types.ts`.
- Изменение контракта согласуют все трое. После него перегенерируются `contracts/*.json`,
  а `tests/test_contracts.py` должен оставаться зелёным.

### Формат ошибок

Любая ошибка API содержит поля `detail`, `code` и `meta`.

- Коды загрузки задаёт ядро через `IngestError`: `unknown_role`, `missing_file`,
  `empty_file`, `not_xlsx`, `bad_format`. Ответ — 422, роль файла передаётся в `meta.file_role`.
- Остальные коды задаёт API: 404, 409, 422, 503, 500.
- Коды ошибок описаны в `docs/API.md`; обзор для запуска — в `README.md`.
- При 500 наружу не уходит трассировка, она пишется в лог.

### Загрузка данных

Разбор всех XLSX занимает около 11 секунд. Поэтому `Dataset`
создаётся при старте процесса и хранится в памяти, а не читается заново на каждый запрос.
Пути к данным строятся от расположения кода, а не от текущей папки.

### Интерпретация результата

Сервис не выдаёт оценку за факт.

- Остаток IEK помечается как нижняя граница.
- Отсутствующая цена показывается как «нет данных», а не как ноль.
- Ответ LLM из кэша помечается.
- Без ключа и без кэша сводка честно недоступна (503), а расчёт работает полностью.

### Проверка изменений

Перед каждым коммитом выполните из корня проекта `pytest -q` в активированном Python-окружении: macOS — zsh/bash, Linux и Windows WSL — bash. Все тесты должны пройти. Каждая проверка из ТЗ —
отдельный тест в `tests/engine/test_acceptance.py`. Инварианты ответа:

- сумма qty-компонентов равна `recommended_qty`;
- количество не меньше нуля и кратно `moq`;
- нет NaN.

### Воспроизводимость

В подготовленном Python-окружении запуск из корня проекта состоит из двух команд: `pip install -r requirements.txt` и `python -m app`. Терминал: macOS — zsh/bash, Linux и Windows WSL — bash, Windows без WSL — CMD. После запуска доступен `http://localhost:8000`; подготовка окружения описана в `README.md`.

- Node не нужен, потому что `frontend/dist` закоммичен.
- Ключи не нужны: LLM опциональна.
- Тяжёлые зависимости (torch, transformers) в `requirements.txt` не добавляются.
- Второй способ запуска — Docker-образ из того же репозитория.

### Совместная работа

Командный порядок проекта предусматривает работу в `main` без веток.

- Каждый правит только свои файлы и перед коммитом делает `git pull --rebase`.
- Коммит — каждый час, каждый под своим аккаунтом (п. 6.5–6.6 Положения).

## Оформление документации

Документация использует единый Markdown-стиль. Тип документа определяет оформление шапки; язык, таблицы и блоки кода оформляются одинаково.

| Тип документа | Шапка и навигация | Примеры |
| :-- | :-- | :-- |
| Обзор или справочник | Центрированные название, описание и бейджи подтверждённых технологий; содержание по разделам H2 | `README.md`, `docs/API.md`, `docs/design.md`, `docs/data-profile.md`, `docs/backtest.md`, `docs/structure.md`, `frontend/DESIGN.md` |
| План, задание или инструкция | Обычный H1, краткое описание и статус при необходимости; содержание для документов длиннее 80 строк | `docs/plans/`, `docs/tasks/`, `frontend/PLAN.md`, `frontend/AGENTS.md`, `frontend/design-contract.md`, `frontend/implementation-handoff.md` |

- В каждом файле один H1; разделы используют H2, подразделы — H3 без пропуска уровней. Номера задач и разделов сохраняются, если на них опираются перекрёстные упоминания.
- Заголовки и основной текст — на русском; технические имена сохраняются. Пути, команды, переменные и значения оформляются в обратных кавычках.
- У блоков кода указан язык. Перед командой заданы рабочая папка и терминал, после — ожидаемый результат.
- Ссылки в содержании ведут только на заголовки текущего файла. Другие документы упоминаются как пути в обратных кавычках.
- Бейджи используют `for-the-badge` без обёртки в ссылку. Версии подтверждаются manifest, lockfile, `requirements.txt` или `Dockerfile`.
- Планы и исходные задания сохраняют собственный статус: их требования нельзя выдавать за текущее состояние реализации.

## Границы проекта

В текущую версию не входят:

- отдельный сервер БД: утверждения лежат в SQLite `var/app.db`, прогоны живут в памяти;
- авторизация, история прогонов, переключатель светлой и тёмной темы, мультиязычность;
- реестры и абстракции «на будущее»;
- автоматическая отправка заказа поставщику: её запрещает ТЗ.
