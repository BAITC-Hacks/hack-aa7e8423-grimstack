Ты работаешь в репозитории команды GrimStack (хакатон HackAlem AI, кейс «Автоматический
расчёт заказов поставщикам»). Прочитай `docs/design.md` целиком, особенно §1, §5, §6, §7.

если чего-то не хватает, спроси, а не обходи.

## Твои файлы (правишь только их)

`frontend/**`, `README.md`. Остальное принадлежит другим участникам, ты это только читаешь.

## Стек

- Vite + React + TypeScript в `frontend/`.
- Графики — Recharts.
- Интерфейс на русском, числа форматировать через `Intl.NumberFormat('ru-RU')`.
- Dev-прокси Vite: `/api` → `http://localhost:8000`.
- Типы в `frontend/src/api/types.ts` повторяют `app/contracts.py` один в один.
- Пока API не готов, работать на моках: при `VITE_MOCK=1` клиент отдаёт JSON из
  `contracts/`. Файлы лежат вне `frontend/`, поэтому нужен `server.fs.allow`.

## Экран (один, плюс боковая панель)

1. **Панель параметров.** Поля:
   - поставщик (все / IEK / SE) и категория — из `GET /api/meta`;
   - метод: «Наш расчёт» (`analyze`) или «Excel-метод» (`baseline`);
   - срок поставки L и период R — плейсхолдер берётся из дефолтов поставщика;
   - уровень сервиса;
   - прирост %.

   Кнопка «Рассчитать» → `POST /api/runs`.
2. **KPI-плитки** из `RunResult.kpi`:
   - позиций к заказу;
   - критичных;
   - сумма (только SE, у IEK цен нет — так и подписать);
   - исключено разовых, шт;
   - восстановлено упущенного спроса, шт;
   - позиции с излишком.
3. **Таблица, сгруппированная по поставщикам.** В заголовке группы: название, число
   строк, сумма, статус «Черновик / Утверждён» и кнопки «Утвердить», «Экспорт XLSX»,
   «Сводка». Колонки строки:
   - код 1С, артикул, наименование;
   - остаток — со значком «≈» и подсказкой, если `stock_source = estimate_lower_bound`;
   - в пути, прогноз/мес, рекомендация;
   - Excel-метод (`baseline_qty`), разница подсвечена;
   - кратность;
   - итог — поле ввода `final_qty` с шагом `moq`, сохранение через `PATCH`, ошибку 422
     показать у ячейки;
   - срочность — бейдж: critical «Срочно», high «Скоро», planned «Плановый»;
   - обоснование — `explanation`, обрезанное, полностью в подсказке.

   Сортировка по срочности, затем по сумме. После утверждения поставщика его строки
   нельзя редактировать.
4. **Боковая панель по клику на строку** (`GET /api/sku/{supplier}/{sku}/history`):
   - линейный график по месяцам: `raw` (сырые продажи), `cleaned` (без разовых),
     `restored` (с упущенным спросом) и `forecast` (пунктир);
   - месяцы, где `stockout` не null, затенены, `oneoff_events` отмечены точками
     с подсказкой;
   - «водопад» из `components`: компоненты `kind="qty"` дают ступени, которые в сумме
     равны `recommended_qty`; `factor` показать как множители прогноза (×1.17 и т.п.),
     `info` — как справочные строки;
   - флаги строки (`flags`) — чипами с понятными подписями.
5. **Загрузка своих выгрузок** — отдельная вкладка или модалка: выбор поставщика и
   6 полей-файлов по ролям (`monthly_sales`, `monthly_stock`, `sales_tx`, `in_transit`,
   `moq`, `seasonality`; первые четыре обязательны) → `POST /api/datasets/{supplier}`.
   Ошибку 422 показать у поля из `meta.file_role`. После успеха запускать расчёты
   с этим `dataset_id`.
6. **Сводка:** `POST /api/runs/{id}/summary?supplier=` — текст в модалке с пометкой
   «из кэша», если `cached`. На 503 — понятное сообщение, кнопка без падения.
7. **Состояния обязательны:** загрузка (скелетон), ошибка (текст `detail` из `ErrorBody`
   и кнопка «Повторить»), пустой результат («Заказывать нечего»).

## Сборка

`npm run build` → `frontend/dist`. **`dist` коммитим**: жюри запускает только Python,
FastAPI раздаёт эту папку.
