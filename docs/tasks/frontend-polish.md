## Контекст задания

Промпт для Codex: вставить целиком.

Ты работаешь в `frontend/**` репозитория GrimStack (кейс «Автоматический расчёт заказов
поставщикам»). Интерфейс проверен на реальных данных в браузере: на 1440 px, на 800–968 px
и на телефоне 375 px. Навигация, панель товара и мобильная раскладка в порядке, ошибок
в консоли нет. Ниже — правки по степени влияния на жюри. Начни с `git pull`.

Команды выполнять в терминале zsh/bash на macOS или WSL/Ubuntu на Windows:
команды npm — в `frontend/`, команды Python и Git — в корне репозитория.

## Границы изменений

- Правишь только `frontend/**`. Контракт `app/contracts.py` не меняешь.
- Ядро (`app/engine`) сейчас правит Aliar: убирает ложную «сезонность» из обоснований.
  Причины вида «Октябрь — сезонный пик (×1.21)» у мелких позиций исчезнут сами — во
  фронте их не трогай.
- В конце: `npm ci && npm run build`, закоммитить `frontend/dist`.

## Приоритет P1: видимость ключевых данных

### 1. «Обоснование» должно быть видно без горизонтальной прокрутки

Сейчас это последняя колонка таблицы (`App.tsx`, строка с `<th>Обоснование</th>`). Даже
на 1440 px от неё видна одна буква «О». Обоснование каждой строки — обязательное
требование кейса.

- Убери колонку «Обоснование».
- Выведи `line.explanation` второй строкой в ячейке товара (`.productCell`) под названием:
  мелкий приглушённый текст (`--text-muted`, `--font-xs`), до двух строк
  (`-webkit-line-clamp: 2`), полный текст в `title`.
- Уменьши `min-width` у `.tableScroll table` (сейчас `82rem`), чтобы таблица помещалась
  на 1440 px. Проверь, что рядом со строкой нет горизонтальной прокрутки.

### 2. Верхние KPI на «Обзоре»

Сейчас там «Исключено разовых продаж 143 683,5» и «Восстановлено спроса 31 085,9»: дробные
штуки без единиц. Главный денежный аргумент при этом спрятан внизу (`overviewFoot`).
Замени четыре плитки на:

| Плитка | Значение | Подпись под числом |
| :-- | :-- | :-- |
| Позиций к заказу | `kpi.lines_to_order` | — |
| Срочные позиции | `kpi.critical` (красным, как сейчас) | «у N остаток оценочный — сверьте в 1С». N = число строк с `urgency === 'critical'` и флагом `approx_stock`; если N = 0, подписи нет |
| Сумма заказа | `kpi.total_amount` компактно: «36,1 млн ₸» (`Intl.NumberFormat('ru-RU', { notation: 'compact', maximumFractionDigits: 1 })`) | «только Systeme Electric — у IEK нет цен», если у части поставщиков `total_amount === null` |
| Позиции с излишком | `kpi.overstock_lines` | «запас выше целевого уровня» |

- Для подписи добавь в `KpiMetric` (`shared/ui/index.tsx`) необязательный проп `hint`,
  стили в `ui.module.css`. Отдельный компонент не заводи.
- Блок `overviewFoot` («Позиций с излишком…», «Оценочная сумма…») удали: он переехал в плитки.
- «Исключено разовых» и «Восстановлено при дефиците» остаются в «Аналитике»
  (`analysisFacts`), но целыми числами. Единицы у позиций разные (шт и м), поэтому пиши
  «ед.», а не «шт».

### 3. «Аналитика → Где расчёты расходятся»

`ComparisonChart` (`features/RunCharts.tsx`) сортирует по относительной разнице, и в топ
попадают только позиции, где Excel = 0. Жюри делает вывод «наш метод просто заказывает
больше», хотя это не так. Нужно:

- взять 4 позиции, где наш заказ **больше** Excel (сортировка по `recommended_qty − baseline_qty`
  по убыванию), и 4, где **меньше** (по возрастанию);
- подпись справа — «4 больше и 4 меньше Excel-метода»;
- в таблице-дублёре добавить колонку «Разница» со знаком;
- над графиком одна строка со счётчиками: «Меньше Excel-метода: N позиций · больше: M».
  На текущем расчёте это 231 и 278: наш метод не «всегда заказывает больше».

Примеры «меньше» из реальных данных:

- ATLAS A398 (SE `300200428_`): у нас 110, у Excel 200 — спрос снижается (×0.83);
- Сжим У 731М (SE `130300026_`): 560 против 1 120.

### 4. Результаты бэктеста в «Аналитике»

Это самое сильное доказательство, а в интерфейсе его нет. API уже отдаёт отчёт:
`GET /api/backtest` (404 `backtest_not_found`, если файла нет).

- В `ProcurementApi` добавь `getBacktest(): Promise<BacktestReport | null>`:
  - `liveClient` — `request('/backtest')`, на 404 возвращает `null`;
  - `mockClient` — `null`.
- Тип `BacktestReport` опиши минимально, только используемые поля (ниже), в
  `ProcurementApi.ts`: в `app/contracts.py` этого ответа нет, `types.ts` не трогай.
- Новая `SectionPanel` в «Аналитике», кикер «ПРОВЕРКА НА ИСТОРИИ», заголовок
  «Наш метод против Excel-метода». Таблица по поставщикам:

  | Поставщик | Ошибка прогноза: наш / Excel | Лучше на | Уровень сервиса: наш / Excel / цель |
  | :-- | :-- | :-- | :-- |

  - «Ошибка прогноза» — WAPE: `suppliers[S].wape.cleaned.analyze.wape` и
    `…baseline.wape`, в процентах с одним знаком (23,0 % / 27,5 %);
  - «Лучше на» — `1 − analyze / baseline` (SE: 16,6 %, IEK: 2,0 %). Не приукрашивай:
    IEK почти вровень, так и показывай;
  - «Уровень сервиса» — `suppliers[S].service_level.analyze.share`, `…baseline.share`,
    `…target`, в процентах.
- Под таблицей одна строка: «Заморожено сверх целевого запаса (SE, на 22.09.2026):
  37,2 млн ₸ · 261 позиция». Значения берутся из `suppliers.SE.frozen_capital_now.amount`
  и `.skus`.
- Ещё ниже мелким текстом: «6 контрольных точек, март–август 2026; прогноз строится только
  по данным до даты точки. Метод и оговорки — `docs/backtest.md`».
- Если отчёт `null` — блок не показывать. Состояние загрузки — `Skeleton`.

## Приоритет P2: полировка

### 5. Кольцевая диаграмма

Пункт «Без заказа: 0» всегда равен нулю: в `lines` попадают только строки с заказом.
Убери его из `urgencies` в `RunCharts.tsx` и из фильтра «Срочность» на странице заказов.

### 6. График истории

В `features/historyChart.tsx` сейчас три линии похожего зелёного. Палитра проверена
валидатором dataviz (все проверки PASS на белом фоне):

| Ряд | Цвет | Толщина и начертание |
| :-- | :-- | :-- |
| «Продажи» (сырые) | Фон, `--border-strong` | 1 |
| «Без разовых» | `#1F7A55` | 2 |
| «Восстановлено» | `#B8741F` | 2 |
| «Прогноз» | `#3563B8` | 2, пунктир (`dashArray: 6`) |

Добавь их токенами в `styles/tokens.css` (`--series-1…3`), hex в компоненте не пиши.
Между зелёным и янтарным различимость для протанопов на границе (ΔE 7,8), поэтому
легенда и пунктир у прогноза обязательны. Они уже есть — не убирай.

### 7. Деньги без копеек

В `shared/format.ts` у `moneyFormatter` поставь `maximumFractionDigits: 0`:
«36 108 635 ₸», «960 028 ₸».

### 8. Штуки целыми

`formatQty` — целые числа (`maximumFractionDigits: 0`), чтобы вместо «910,3 шт»
было «910 шт». `formatNumber` для множителей и шагов «водопада» не меняй:
там нужны десятые (×1,89).

## Критерии готовности

- На 1440 px обоснование видно у каждой строки без прокрутки.
- На «Обзоре» 4 плитки: позиции, срочные с подсказкой про оценочный остаток, сумма
  в «млн ₸», излишки.
- В «Аналитике» есть блок бэктеста с цифрами из `/api/backtest` и честным IEK.
- «Где расчёты расходятся» показывает оба направления.
- `npm run build` без ошибок, `frontend/dist` закоммичен.
- Проверено в браузере на `python -m app`: 1440, 768, 390 px.
- Коммит под своим аккаунтом, перед ним `git pull --rebase`.
