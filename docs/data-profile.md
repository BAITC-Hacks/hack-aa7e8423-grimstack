# Профиль данных: методика для сервиса автозаказа (ТОО «Электрокомплект», поставщики IEK и Systeme Electric)

Бриф собран из шести отчётов: tx-iek, tx-se, stocks-stockout, sales-seasonality, transit-moq, keys-coverage. Ключевые числа и противоречия перепроверены по данным. Пометка **[✔]** значит, что число пересчитано повторно. «Гипотеза» — предположение, данными не подтверждено.

## 0. Главное
1. **Основной ряд спроса — помесячные продажи 1С**: янв.2024–авг.2026, 32 закрытых месяца. Транзакции («Динамика продаж») доступны только с 01.2025. Они нужны для построчной очистки (разовые заказы, паллеты), распределения продаж по дням при stockout и ссылок на документы в обосновании.
2. **У SE транзакции в 2,11 раза больше помесячного файла.** Помесячный файл: 3 078 431 шт за 01.2025–08.2026, транзакции: 6 496 329 **[✔]**. Разница — «паллетный» поток у 19 SKU коробок. Если его вычесть, остаётся 3 066 525 шт, это −0,4% к файлу **[✔]**. Паллетный поток не проходит через складские остатки. Пример 030200239_: в транзакциях 224–6 624 шт в месяц, а в помесячном файле с 03.2025 продаж 0, остаток всё это время 1 шт **[✔]**. Гипотеза: это транзит или прямая поставка клиенту.
3. **«нач. остаток» — остаток на 1-е число месяца** и у IEK, и у SE **[✔]**. Проверка балансом R = S[m+1] − S[m] + Q[m]: при чтении «на начало» R = 0 в 54,9% (IEK) и 61,4% (SE) SKU-месяцев, при чтении «на конец» — только в 27,8% и 19,8%. В keys-coverage смысл остатков SE назван неизвестным, этот вопрос закрыт.
4. **У IEK продажи в штуках падают примерно на 15% в год, при этом выручка стабильна.** Сезонность партнёра посчитана по выручке, поэтому для заказа в штуках она не подходит.
5. Правило разового заказа из ТЗ в чистом виде (q > 5×медиана и q > Q3+3·IQR) режет 39,6% объёма IEK и 65,8% объёма SE. Нужна связка из трёх шагов: сначала отделить паллетный поток, затем применить правило с проверкой нерегулярности, затем обрезать строку, а не удалять её целиком.

## 2. Каноническая модель

- **Нормализация кода:** `str(x).strip()`, и больше ничего. Проверено keys-coverage на 20 парах файлов: нормализация добавляет 0 совпадений. `_` — часть кода: `250600007` и `250600007_` — разные карточки, у первой остаток 0, у второй 334 на 01.09 **[✔]**. Длина кода до 20 символов, встречаются обрезанные коды. Буквенные коды (`ярп…`, `ст-…`, `ATN…`) — настоящие. Пересечений между IEK и SE нет ни по кодам, ни по артикулам: поставщик определяется по семейству файлов. ITK, BRITE, ELECOR, ONI, ARMAT, E-PRO, KARAT, КВАРТА, ОКТАВА относятся к IEK.

Таблицы:

- `sku(supplier, code PK, name_1c, name_supplier, unit, article, group4 = code[:4] для кодов вида \d{9}_, category_se, assortment_section_iek, flags{excl_bang, excl_star3, generica, tdm, new, keep_1m, buy_pack_note, legacy_code})`.
- `sales_monthly(supplier, code, month, qty)` — основной ряд. Для 22 SKU SE, которых нет в 1С-выгрузках (например 300200589_), дополнять из колонок 6–40 TDSheet.
- `sales_tx(supplier, doc, date, number_series{200,300}, code, qty)`, ключ (doc, code). Колонки клиента нет.
- `stock_monthly(code, month, opening)` и `stock_current(code, qty, reserved, source, is_lower_bound)`.
- `in_transit(code, shipment, route{РФ,ПП,''}, order_date, eta, qty)`.
- `moq(code, multiple)`; `supplier_cfg(supplier, lead_time, review_period, service_levels)` — конфиг.
- Производные: `clean_monthly(code, month, qty_raw, qty_oneoff_removed, stockout_type, in_stock_share, qty_restored)` и `order_line(... обоснование)`.

## 3. Пять must-have

### MH1. Базовая потребность
**Входы:** очищенный ряд `sales_monthly`, текущий остаток, в пути, MOQ, категория (SE: `Категория 2026`; IEK: ABC по объёму за 12 месяцев или group4), тренд и сезонность.

**Формула:**

`заказ = ceil_к_кратности( max(0, прогноз(LT + R) + SS − (остаток_сейчас + в_пути_до_горизонта)) )`

- Прогноз = уровень × тренд × сезонность.
- Уровень — среднее очищенного ряда за 6–12 закрытых месяцев. **Сентябрь 2026 не использовать.**
- SS — страховой запас по уровню сервиса категории.

**Сегментация по Syntetos–Boylan** (последние 12 месяцев):
- smooth + erratic: IEK 38% SKU / 97% объёма, SE 48% / 98%. Прогноз по формуле выше.
- intermittent + lumpy: 62% / 2,6% и 52% / 1,8%. Режим min-max с минимумом, равным медианному размеру продажи (≈3–4 шт).
- Нет продаж за 12 месяцев (IEK 390, SE 23) → не заказывать.

**Бейзлайн менеджера SE** для сравнения: прогноз на 3 месяца = JJA26 × (1 + Кэф.Сез) → 114 SKU, ≈30,5 млн по себестоимости. Это гипотеза: колонка «Заказ» пуста.

**Демо-SKU («меняем источник → меняется результат»):**
- 010500006_ ВА47-29 16А: крупнейший SKU IEK, в пути 30 000.
- 130300791_ Труба Ø40: остаток на 01.09 = 2 **[✔]**, впереди пик в октябре.
- SE 030200193_ IMT35150: в пути 37 800 = 10 × кратность 3 780.

### MH2. Сезонность и тренд
**Метод:**
- Профиль считать **в штуках**, по поставщику или по группе group4, на ряду, очищенном от stockout и разовых заказов. Нормировать так, чтобы среднее было 1.
- Собственный профиль SKU давать только при ≥24 месяцах с продажами, r(2024, 2025) ≥ 0,6 и r(2026) ≥ 0,6, и то в смеси 0,3·свой + 0,7·группа.
- Почему так: медиана корреляции профилей SKU 2024 и 2025 равна 0,04. Shape-WAPE: свой профиль 0,384, профиль поставщика 0,341 у IEK.
- Группы с подтверждённой сезонностью:
  - IEK 1303 (трубы): размах 4,4×, октябрь 1,72, январь–март 0,39–0,52;
  - IEK 0105 (ВА47-29): 2,1×;
  - SE 0302 (коробки): 2,0×.
- Тренд по SKU: T = сумма последних N месяцев / те же месяцы год назад, clip [0,67; 1,5], сжатие T = 1 + (T − 1)·n/(n + 6). Бэктест WAPE: IEK 0,309 против 0,367 без тренда, SE 0,130 против 0,209.

**Изъяны сезонности партнёра:**
- считается по выручке;
- коэффициенты 2026 нормированы на 9 месяцев;
- неполный сентябрь занижает сентябрьский коэффициент (IEK 0,97 против 1,10 по штукам);
- SE-ряд не нормирован (среднее 0,9953).

Профиль IEK по штукам за 2024–2025: `[0.83 0.87 0.76 1.01 1.00 0.99 1.16 1.18 1.10 1.17 0.99 0.93]`.

**Демо:**
- 130300792_ Труба Ø50 (м): октябрь 2024 = 8 685, октябрь 2025 = 13 414, январь 585–652.
- 010500006_: март ≈ 11–12 тыс., июль ≈ 24–27 тыс.
- SE 030200201_ IMT35101, устойчивый рост: 148 911 за 2024 → 231 760 за 2025 → 199 401 за 8 месяцев 2026, то есть +29% к среднему месяцу 2025 **[✔]**.

### MH3. Упущенный спрос (stockout)
**Входы:** остатки на начало месяца (open = S[m], close = S[m+1]), помесячные продажи, транзакции для оценки доли дней в наличии.

**Флаги** (SKU активен, если были продажи в 6 месяцах до и в 6 месяцах после):
- `full`: open ≤ 0 и close ≤ 0;
- `start`: open ≤ 0, close > 0;
- `end`: open > 0, close ≤ 0;
- «эффективный stockout»: open < 0,25 × база.

Доля SKU-месяцев со stockout: IEK 7,5% (3 127 из 41 789), SE 0,7% (79). Модуль нужен в первую очередь для IEK. Медиана продаж к базе: full 0,00 (80% месяцев с нулём), start 0,21, ok 0,68.

**Восстановление аддитивное:** `спрос = q_очищ + база × (1 − доля_дней_в_наличии)`.
- База — медиана за 6 предыдущих месяцев в наличии, минимум 3 таких месяца. Ограничение сверху 2 × база (гипотеза).
- Бэктест: смещение 1,00, медианная ошибка 0,45 против 0,50 у факта. Метод q/доля нестабилен.
- Доля дней в наличии для 2025+ считается по транзакциям (рабочие дни пн–сб). Для 2024 умолчания: full = 0, start = end = 0,5.
- **Порядок важен:** сначала вырезать разовый заказ, потом восстанавливать. Месяцы `end` в медиане на 80% состоят из одной крупной строки.

**Демо (IEK, все проверены [✔]):**
- 010300096_ УЗО АВДТ 32 40А: май 2025 open 741, продано 734 (одна строка 630 шт 15.05) → июнь open 0, продано 40 → июль приход. Полная цепочка «разовый заказ → stockout».
- 130200124_ Шина N ШНИ-14: open 0 в фев–апр 2025, продажи 0/0/43, в мае приход 1 418.
- 260100138_ Наконечник JG-6: январь 2026 open 0/close 0, продано 18 при базе ≈ 1 200.
- Запасной пример: 130300792_, август 2026 open 0, продано 946 против 15 620 в июле.

### MH4. Разовые крупные заказы
**Входы:** транзакции (с 2025), MOQ/кратность SE, помесячный файл.

**Метод:**
1. **SE: сначала отделить паллетный поток R5**: Кратность ≥ 50, q ≥ Кратность и q кратно Кратности. Это 19 SKU, 2 363 строки, 3,65 млн шт, 53% объёма транзакций. Поток регулярный (13–21 месяц из 21), это отдельный канал, а не разовые заказы. В помесячном файле его нет, поэтому база из файла уже «чистая».
2. **Правило разовой строки** (n ≥ 5 строк у SKU, для SE лучше n ≥ 20; статистики по прошлому окну), все условия одновременно:
   - q > 5 × медиана строк SKU;
   - q > Q3 + 3·IQR;
   - q ≥ медиана ненулевых месяцев SKU (для SE — ≥ среднего месяца);
   - такие строки у SKU были не более чем в 3 (IEK) или 4 (SE) месяцах из 21.

   Эффект: IEK 788 строк, 56 263 шт (1,46%); SE после R5 303 строки, 52,7 тыс. шт (1,7%). Дополнительно «беспрецедентная» строка: q ≥ 2 × вторая по величине строка SKU (IEK 314 строк, 1,41%).
3. **Обрезать, а не удалять:** срезать до max(5·мед, Q3 + 3IQR, M_nz). Для правила B это снимает 2,5% объёма вместо 6,3%.
4. Из транзакций в помесячную ячейку переносить вычет с ограничением снизу нулём.
5. **Проектный документ:** ≥3 отмеченных строк в одном `Документ` (IEK: 62 документа). SKU×день с несколькими документами склеивать: 14% крупных SKU-дней у IEK, 9,5% документов у SE — продолжение предыдущего в пределах 10 минут с тем же SKU.

**Демо:**
- IEK 130200305_ «Петля LOOP»: 210 000 шт, накладная 20000064179 от 09.06.2025, единственная продажа SKU; в помесячном файле этого SKU нет **[✔]**. Исключается явно.
- IEK 010500008_ ВА47-29 25А: 7 488 шт, 02.09.2026, документ 20000099834; это 2,9× от второй по величине строки. Ловит только правило «беспрецедентной» строки.
- SE 030300013_ У-195: паллеты 6 480 (03.2025) и 10 908 (06.2025) при помесячном файле 108 и 0. Или 030200192_: 90 000 шт 06.05.2025.

### MH5. Итоговый список по поставщикам с обоснованием
Группировка IEK / SE. Поля строки:
- код, артикул (для экспорта; IEK: 1 804 из 1 922 активных, остальным «нет артикула»), название;
- уровень, тренд T, сезонный коэффициент;
- исключённые разовые строки (документ, дата, количество);
- восстановленные месяцы stockout (тип, доля дней в наличии);
- остаток и его источник, в пути с ETA, LT/R;
- «потребность X → округлено до кратности K → заказ Y»;
- флаги (`!!!`, `NEW`, «поддерживаем склад 1 мес», единица закупки);
- для SE сумма по «СС реал»; для IEK суммы нет.

Отдельные блоки: «не заказывать» с причиной и «срочно». Срочных у IEK 142 активных SKU с оценкой текущего остатка ≤ 0, у SE 7.

## 4. Остаток, в пути, lead time, MOQ
- **Текущий остаток SE:** из TDSheet. Доступно = Свободный + Витрина + Остаток ТЗ + РЦ ЕКТ + Розничный, то есть логика менеджера, **[✔]** по колонке «Запас». Нельзя считать как S_01.09 − продажи сентября: сумма складов TD = 424 386, а по такой формуле вышло бы 163 910, потому что в сентябре были приходы. Помесячный остаток SE — это сумма складов, а не только «Остаток»: S_01.09 совпадает с суммой складов у 171 из 474 SKU, с «Остаток» только у 98 **[✔]**.
- **Текущий остаток IEK:** в данных нет. Оценка = max(0, S_01.09 − продажи 1–21.09) с пометкой «нижняя граница». У 102 SKU разность отрицательна — значит, приход точно был. Обычный месячный приход IEK 100–344 тыс. ед. — главная неопределённость.
- **В пути IEK:** сумма 6 колонок, все ETA 30.09–15.10, то есть в пределах LT. **В пути SE:** колонка 54, 7 SKU.
- **Lead time:**
  - IEK по заголовкам «Пути»: без префикса 12 дней, «ПП» 24, «РФ» 35–40. По умолчанию 24 (≈83% объёма идёт через ПП и без префикса), консервативно 40.
  - SE: в данных нет. По умолчанию 40 дней (гипотеза), параметр в конфиге.
- **Review period:** IEK 7 дней (4 заказа за 18 дней). SE 30 дней: топ-100 SKU получают приход в 7 месяцах из 12.
- **MOQ / кратность:**
  - IEK `Мин. разр. к отгр.` — это кратность: 303 из 305 ячеек пути кратны MOQ, при MOQ > 1 — 133 из 135 **[✔]**. Округлять вверх. Нет MOQ у 258 активных SKU (0,43% объёма) и пусто у 15 → брать упаковку из названия `(N)`/`(N/M)`, иначе 1.
  - SE `Кратность`: 3 600 и 3 780 — паллеты. Кратность 0 или `!!!` → не заказывать.
  - Единицы закупки IEK: кабель ITK «305м» (6 SKU) — заказ кратен 305 м, поставщику уходит в бухтах; ТУТ (24 SKU) — упаковка в метрах из названия; аксессуары КМП (54 SKU) — см. §8.
  - 34 SKU IEK с пометкой «поддерживаем склад на 1 мес» → целевое покрытие 1 месяц.
