# Передача дизайна в реализацию

Прочитай `AGENTS.md`, `PLAN.md`, `DESIGN.md`, `design-contract.md`, `../docs/tasks/frontend.md` и `../app/contracts.py`. Основной визуальный референс хранится в `references/main-screen.png`.

1. Создай один экран Vite + React + TypeScript. Начни с макетных данных через `VITE_MOCK=1`; все компоненты обращаются к `ProcurementApi`, а не к JSON напрямую.
2. Повтори композицию макета: компактная верхняя панель, четыре главных KPI, таблицы двух поставщиков, контекстная панель SKU справа. До выбора строки таблица занимает всю ширину.
3. Возьми тёмные значения из `design-tokens.json`, перенеси их в общий `src/styles/tokens.css` и применяй через компоненты `src/shared/ui/`. Правила композиции и адаптации находятся в `DESIGN.md`: от 1440 px используй примерно 58/42 для таблицы и деталей; ниже — выдвижную панель; до 640 px — карточки и полноэкранные детали. Проверь 320, 390, 768, 1024, 1440, 1920 px и 200 % масштаб.
4. Для истории используй `apexcharts` + `react-apexcharts`: светлая линия факта, переключаемые очищенные/восстановленные ряды, голубой пунктир прогноза, красное затенение только реальных stockout-месяцев. Рядом обеспечь табличное представление чисел.
5. Выведи «лесенку» из `components` без смешивания `qty`, `factor` и `info`. Сохраняй `final_qty` через PATCH, затем перечитывай прогон; утверждение блокирует правку, XLSX скачивается из backend.
6. Первая рабочая версия должна показывать `IEK:130300792_` и `SE:030200201_` из `sample_run.json`, демонстрировать различие с Excel-методом и отличать моковые данные от live-ответа. Значения примера не закрепляй в UI.
7. Прежде чем считать frontend готовым, пройди сценарий жюри из `DESIGN.md` на реальном API, проверь все ширины из пункта 3, клавиатуру, 422/409/503 и содержимое XLSX.

Изменяй только `frontend/**`. Обновление корневого README выполняется позже по заданию frontend, когда рабочий сайт и ссылка на деплой действительно есть.
